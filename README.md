# Millis — 沉浸式毫秒時鐘 (PWA)

全螢幕、無干擾、顯示到毫秒的網頁時鐘。可以安裝到手機／桌面當成獨立 App，離線也能用。
純靜態：沒有框架、沒有打包工具、沒有外部字型，整包丟到任何靜態空間就會動。

## 快速試玩

```bash
cd clock
python3 -m http.server 8080
# 打開 http://localhost:8080
```

> 安裝與離線功能需要 **HTTPS** 或 **localhost**。用 `file://` 直接開只會看到時鐘、裝不了 App。

## 設定（點右下角 ⚙）

**時間**
- 時制：24 / 12 小時
- 時區：跟隨裝置，或從常用清單／完整 IANA 時區清單挑一個（夏令時間會自動處理）
- 顯示秒、顯示毫秒、顯示日期、顯示時區名稱

**外觀**
- 深淺模式：跟隨系統 / 淺色 / 深色
- 色調：中性、琥珀、薄荷、冰藍、玫瑰（每個色調都有深淺兩版）
- 字型：黑體 / 襯線 / 等寬 / 圓體（都用系統內建字型，不連網）
- 字重：極細 / 細 / 標準 / 粗
- 字體大小：40% ~ 160%

**效果**
- 發光：無 / 柔和 / 強烈
- 冒號閃爍（跟秒精準同步，不會漂）
- 切換設定時淡入
- 控制列自動隱藏：2 / 3 / 5 / 10 秒 / 不隱藏
- 螢幕不休眠（Wake Lock）

所有設定存在瀏覽器本機，下次打開就在。按「恢復預設值」可重來。

## 幾個關鍵的技術決定

**1. 用 `requestAnimationFrame`，不用 `setInterval(…, 1)`**
`setInterval` 最快大約只有 4ms，而且會跟螢幕更新錯開、看起來會頓。rAF 跟著螢幕的節奏跑（60Hz 約 16ms、120Hz 約 8ms），畫面最順也最省電。

**2. 每一幀都重新問系統現在幾點**
不是自己 `+1ms` 累加，所以分頁被切走再切回來、或裝置休眠過，時間都不會跑掉。

**3. 只有數字真的變了才動 DOM**
時分秒一秒才變一次，沒必要每幀重寫。搭配 CSS `tabular-nums`（等寬數字），毫秒狂跳時整排數字也不會左右抖。
> 這裡有個容易踩的坑：判斷「有沒有變」的初始值要用 `null` 而不是空字串，否則「AM 變成空白」這種變化會被誤判成沒變，舊文字就擦不掉。

**4. 時區換算只算一次，不是每幀算**
`Intl.DateTimeFormat` 很貴，每秒跑 60 次會很浪費。做法是每 10 秒算一次「目標時區跟 UTC 差幾毫秒」，之後每幀只做一次加法。10 秒也足夠即時反映夏令時間切換。

**5. 自動縮放保證塞得下**
字型、字重、字級、要不要顯示毫秒，全部都會影響寬度，純 CSS 很難算準。所以量完實際寬高後，用一個 `--fit` 係數收尾，確保在任何螢幕上都不會被切掉。

## 已知限制

- iOS Safari 沒有全螢幕 API。做法是**加到主畫面**後開啟，`display: fullscreen` 就會自然全螢幕。
- Wake Lock 目前 iOS Safari 支援有限；不支援時設定頁會直接標示出來。
- 顯示精度受限於瀏覽器：基於資安考量（防側通道攻擊），`Date.now()` 在部分瀏覽器會被刻意降低精度，誤差在數毫秒等級。當一般時鐘綽綽有餘，但**不適合當競賽計時器**。
